The System

What this is, what an agent is, and how the pieces connect.

What This Is

One application that runs the entire agency. You open it in the morning, and everything that needs your attention is already there - client emails that need replies, ad campaigns that need fixing, invoices that are overdue, meetings that generated action items. All in one place, prioritized, with context already loaded.

There are no separate tools. No switching between Gmail and Google Ads and Stripe and a project tracker. One interface, one task list, one AI that has access to everything.

What an Agent Is

When this spec says "agent," it means something specific: a Claude instance with a set of tools and a job.

Think of it like hiring a specialist. You give them access to the systems they need (Gmail API, Google Ads API, the client database, the timeline), you tell them what their job is (read incoming emails, decide what needs attention, create tasks), and you let them work. That's an agent.

An agent is not magic. It's Claude + tools + instructions. Different agents have different tools and different instructions, but the pattern is always the same: receive input, use tools to gather context or take action, produce output.

Example: The Communication Agent

An email arrives from Ruthy at Nzymes asking about her CPA numbers.

The Communication Agent is a Claude instance with access to: Gmail (read the email), the Timeline (pull Nzymes' recent history), and the Task Queue (create a task). Its instructions say: categorize this message, check the client timeline for context, decide if this needs a task or just a log entry.

It reads the email, pulls Nzymes' timeline, sees there's an active campaign, and creates a HIGH priority task: "Nzymes - Ruthy asking about CPA." By the time you see it in your sidebar, the context is already loaded.

Five Domains, Many Agents

The system is organized into five domains - areas of responsibility. Each domain has as many agents as it needs to get the job done. Communication alone might have three: TrashMan (filters junk), the Comm Agent (reads and categorizes), and the Meeting Agent (extracts action items from transcripts). Monitoring might have one agent per ad platform. The number of agents isn't fixed - it's whatever it takes.

What matters is that every agent, regardless of which domain it belongs to, reads from and writes to the same timeline and task queue. That's how they stay coordinated.

Key Point
Every agent - regardless of domain - reads from and writes to the same two systems: the client timeline (shared memory) and the task queue (shared work list). That's what keeps them coordinated. A Communication agent creates a task, and when you work that task, the AI in the thread can pull from Monitoring tools for ad data if you need it. The domains define what agents watch. The shared infrastructure means any agent can draw on anything in the system when it's time to act.

Two Pieces of Infrastructure

Before diving into what each agent does, you need to understand the two systems they all share. These are covered in detail on their own pages, but here's the concept:

Client Timeline
A chronological log of everything that has happened with a client. Every email, ad change, meeting, task, billing event. Agents read this before acting so they have context. They write to it after acting so nothing is lost. One timeline per client, permanent and append-only.
Task Queue
The single list of all work that needs doing. Every agent creates tasks here. Every task is a chat thread where you work with the AI. Tasks are prioritized (Critical, High, Normal, Low) and appear in your sidebar sorted by urgency. You pull work when you're ready.

These are the two arteries of the system. Every agent connects to both. The timeline is the memory. The task queue is the to-do list. Everything else is built on top of them.

How It Feels to Use

You open the app. The sidebar has your tasks, sorted by urgency. A red item at the top: TheRealSleep's website is returning 503 errors. Below that, orange: Stone & Tile's budget was auto-fixed overnight, review it. Then normal items: Ruthy's email, a meeting with 4 action items to approve, an ExclusiveMatchmaking onboarding step that's blocked on assets.

You click the TheRealSleep alert. The AI has already checked the site, confirmed it's still down, and drafted a message to the client letting them know you're on it. You approve the message, it sends, the task is done.

You click Stone & Tile's budget fix. The AI shows you what happened: broad match keyword went wild, budget was 35% over pace, it reduced the daily cap and added negative keywords. You review, looks good, mark it done.

You click Ruthy's email. The AI pulled Nzymes' timeline, loaded last month's performance data, and drafted a reply with the CPA numbers she asked about. You tweak one sentence, hit send.

That's the system. One app, one sidebar, one pattern: open a task, work with the AI, move on.
